# Rozetka feed builder — налаштування

Автоматично будує XML/YML-фід для Rozetka з вашого Prom.ua-фіда та фіда
постачальника, застосовуючи всю логіку, напрацьовану вручну (мапінг
категорій, ціноутворення під реальну комісію Rozetka, очищення описів,
характеристики).

## Важливий нюанс: таблиця відповідності ID

Ваш живий Prom YML-фід використовує `vendorCode` = **Код_товару** (внутрішній
номер Prom), а фід постачальника ключується на **Ідентифікатор_товару**
(артикул типу `00945-01`) — це різні системи нумерації. Файл
`references/code_to_article.json` — довідник-перекладач між ними,
побудований з вашого xlsx-експорту від 13.09.2026 (3583 записи).

**Обмеження:** нові товари, додані на Prom **після** цієї дати, не будуть
у довіднику — для них зіставлення з фідом постачальника (країна, РРЦ,
свіжа наявність, чисті фото) не спрацює, скрипт просто візьме дані
напряму з Prom (це не помилка, а керована деградація — гірше, ніж з
довідником, але не ламається).

**Як оновити довідник:** принесіть Claude свіжий xlsx-експорт з Prom —
він перегенерує `code_to_article.json` (кілька секунд роботи).
Робіть це приблизно раз на місяць, або коли з'являється багато нових
товарів.

## Що вже готово в цьому репозиторії

- `scripts/build_feed.py` — весь пайплайн
- `.github/workflows/update-feed.yml` — розклад автозапуску (щодня о 8:00 Києва)
- `scripts/requirements.txt` — залежності

## Кроки одноразового налаштування

### 1. Створіть репозиторій на GitHub

- Зайдіть на github.com → **New repository**
- Назвіть як завгодно (напр. `rozetka-feed`)
- **Публічний** (Public) — це потрібно, щоб `raw.githubusercontent.com`
  міг віддавати файл без авторизації
- Завантажте туди весь вміст цієї теки (`scripts/`, `.github/`, цей README)

### 2. Додайте два секрети

**Settings → Secrets and variables → Actions → New repository secret**

| Назва секрету | Значення |
|---|---|
| `PROM_FEED_URL` | Посилання на ваш YML-експорт товарів з Prom.ua |
| `SUPPLIER_FEED_URL` | `https://proteinplus.pro/api/xml2/<ваш токен>.xml` |

Секрети не видно нікому, навіть у публічному репозиторії — GitHub
приховує їх значення завжди, включно з логами запусків.

### 3. Увімкніть Actions і запустіть вручну перший раз

- Вкладка **Actions** → якщо GitHub попросить підтвердити ввімкнення
  workflows — підтвердіть
- Знайдіть **Update Rozetka feed** → **Run workflow** → **Run workflow**
  (зелена кнопка)
- Через хвилину-дві перевірте, чи з'явився файл `feed/rozetka_feed.xml`
  у репозиторії, і чи запуск позначений зеленою галочкою (не червоним
  хрестиком)

### 4. Отримайте постійну URL-адресу файлу

Формат:
```
https://raw.githubusercontent.com/<ваш-акаунт>/<назва-репо>/main/feed/rozetka_feed.xml
```

### 5. Підключіть цю адресу в кабінеті Rozetka

**Товари → Імпорт товарів → Підключити XML-фід** (чи аналогічний пункт)
— вставте адресу з кроку 4. Rozetka сама перечитуватиме файл приблизно
раз на годину.

## Як це підтримувати далі

- **Нічого руками робити не потрібно** для оновлення цін/залишків —
  щодня о 8:00 сам перерахує й запуше свіжий файл
- **Нові категорії Prom** без відповідника в `DIRECT_CATEGORY_MAP`
  (у `build_feed.py`) просто не потраплять у фід — розширювати цей
  словник потрібно вручну (можна повернутись до Claude з проханням)
- **Нові топові товари з повним дослідницьким описом** (nutrition-facts,
  EU-твердження) цей скрипт не пише сам — тільки спрощений опис.
  Раз на місяць варто приносити Claude свіжий список нових товарів
  для якісного опрацювання
- **Тарифна сітка комісії Rozetka** (`BADY_BRACKETS` тощо в
  `build_feed.py`) захардкожена станом на 2026-09-13 — Rozetka може
  її змінити, тоді ціни почнуть рахуватись неточно. Раз на кілька
  місяців варто звіряти з вашим кабінетом

## Перевірка, що все працює

**Actions** вкладка → зелена галочка = все ок. Червоний хрестик →
відкрийте запуск, подивіться текст помилки (найчастіше — неправильний
`PROM_FEED_URL`/`SUPPLIER_FEED_URL` або тимчасова недоступність
джерела).
